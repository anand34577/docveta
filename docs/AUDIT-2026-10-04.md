# Audit, 4 October 2026

A review of the server, web app, Android app and OCR engines after 0.5.2: bugs, gaps against
the roadmap, and what happens as libraries grow. Everything under *Fixed* is in the working tree
with tests where the code can be tested without a database; *Not verified* lists what still needs
a run against PostgreSQL.

## How it was checked

- Code review of the Go server (`internal/…`), web app (`web/src`), Android app and workers.
- Go unit tests (`go test ./...`, `-race` for the AI package), web type-check and production
  build, Python worker tests, Android unit tests (JDK 17) and a debug build.
- The web app driven in Chrome (Playwright) against a mock API at phone (390 px) and laptop
  (1366 px) sizes, light and dark; the Android app on an emulator (Android 37) against the same
  mock: sign-in, SSO round trip, Inbox, document viewer, Ask (including Stop).
- **Not run:** the PostgreSQL integration tests (`internal/app/*_test.go`, gated by
  `DOCVETA_TEST_DATABASE_URL`). See *Not verified*.

## Fixed

### Single sign-on (reported as not working)
| Problem | Effect | Fix |
|---|---|---|
| Issuer's trailing `/` was stripped before discovery | Authentik/Zitadel/Auth0 failed with "issuer did not match" | Issuer kept as typed; both forms tried; the working one saved |
| Redirect URI built from `DOCVETA_BASE_URL`, default `http://localhost:8080` (installers don't change the host) | Every provider rejected the sign-in ("redirect_uri mismatch") | Redirect URI from the address in use (trusted proxies honoured); Admin shows the exact URI |
| Userinfo only read when email was missing | Group rules failed for providers that put groups only in userinfo | Read when email *or* groups are missing |
| `email_verified: "true"` (string) treated as false | No linking with Cognito-style providers | Accepted |
| Error text pointed to "link SSO from Settings", which didn't exist | Dead end | Settings → Security → Single sign-on (connect/disconnect) |
| Android app could only use access tokens with SSO servers | No SSO on phones | Browser sign-in, `docveta://sso` app link protected by PKCE |

### OCR
| Problem | Fix |
|---|---|
| Engines used one recognition model per page, chosen from the space language (default English): Hindi pages lost every line | Per-page script detection on the widest lines, per-line retry for mixed pages, guarded against "noise read as Tamil" (`ppocr.read_lines`, 6 tests) |
| Engines reported the page language, the server ignored it | Document language follows the text unless a person set it |
| Tesseract only read the hinted language | Also Hindi by default (`DOCVETA_OCR_EXTRA_LANGUAGES`) |

### Viewer and sharing (reported)
- Text layer (`z-index: 2`) sat above the floating controls: taps on zoom/turn selected text
  (shared links, Inbox, document page). Controls now sit in an isolated stacking context, can't be
  selected, and don't trigger double-tap selection. Verified by tapping on a touch emulation.
- No fit-to-screen: added *Fit page* / *Fit width*, pinch and Ctrl+wheel zoom, and the same
  controls for pictures.
- Shared links showed recognised photos as a broken image (the "best" file is their PDF).
- The PDF reloaded/redrew whenever its parent re-rendered (new array/function props).

### AI and Ask (reported)
See CHANGELOG *Fixed → Ask*. In short: retrieval (follow-ups, focused passages, per-document cap,
document details in the prompt, document-scoped questions), pgvector, token-aware chunking for
Indian scripts, robust streaming (`<think>` removal, error events, idle timeout, keep-alives,
stop saves the partial answer), readable error messages, conversation management, Markdown, and
the Android stream not being cancelled by Stop.

### Notifications and links
- Links in emails/push used `localhost`; now the remembered or configured address.
- Local Gotify/ntfy/Apprise were blocked for everyone by the SSRF guard; administrators' and
  system channels may now reach the local network, others when allowed in Administration.
- Microsoft 365 / Outlook.com SMTP (AUTH LOGIN only) failed; ntfy titles in Hindi.

### Scale
- Foreign keys without indexes: purging a document scanned the whole `pages` table per OCR run;
  deleting a user scanned documents, history and notes (`00012_fk_indexes.sql`).
- Meaning-based search scanned every stored vector per query (pgvector + HNSW now, bounded top-k
  otherwise).
- Taxonomy lists counted per item (one grouped query now); result totals capped at 100,000;
  facets skipped above 50,000 matches; O(n²) de-duplication in bulk actions.
- Inbox *All reviewed* only changed the loaded page (server-side selection now, in batches).

### Other
- `/metrics` was public (local network only now, or `DOCVETA_METRICS_TOKEN`).
- Inbox shortcuts fired inside dialogs; Esc in bulk dialogs cleared the selection.
- Home page overflowed on phones; list view squeezed titles; Inbox squeezed the preview at 1366 px.
- Android: stuck on "Can't reach the server" with no way to change server; tab colours; page indicator.

## Not verified (needs a PostgreSQL run)

These changes compile and their pure logic is unit-tested, but their SQL has not run against a
database in this audit. Run the integration tests before releasing:

```sh
DOCVETA_TEST_DATABASE_URL=postgres://user:pass@localhost:5432/docveta_test go test -race ./internal/app
```

- Migrations `00011_pgvector.sql` (with and without pgvector installed, and as a user without the
  right to create extensions) and `00012_fk_indexes.sql`.
- pgvector search (`internal/ai/vector.go`: HNSW expression index per size, `SET LOCAL hnsw.*`,
  backfill) on PostgreSQL 16/17 with pgvector 0.7 and 0.8.
- Ask retrieval SQL (`retrieve`, `describe`), lazy conversation creation, rename/delete-all.
- Taxonomy list aggregate, capped totals, `select: "inbox"` bulk updates, OIDC account linking
  and `Unlink`, server settings, detected-language update in `finalize`.

`internal/app/ai_test.go` already covers Ask end to end with a fake model; it will exercise most
of the AI changes.

## Recommendations

1. Run the integration tests against PostgreSQL 17 with and without pgvector (above).
2. Reminders + ICS next: the highest everyday value for bills, insurance and ID renewals.
3. Make *Empty Trash* a background job: with tens of thousands of trashed documents one request can
   outlast a proxy's timeout (it is correct, just long).
4. Hybrid (meaning-based) search returns at most 50 results without "load more"; add paging.
5. A concurrent duplicate upload can slip past the duplicate check (no unique index on
   `(space_id, content_hash)`); low impact, but a partial unique index would close it.
6. Add the mock-API + Playwright screen checks from this audit to CI, at 360 px and 1366 px.
